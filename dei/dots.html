Unity DOTS: referencia aplicada

Guía de consulta para T8 y la ampliación DOTS de Lab 5. No añade una sesión obligatoria al itinerario.

Qué es DOTS

Data-Oriented Technology Stack: tres piezas (ECS, Jobs, Burst) que permiten escalar a miles de entidades manteniendo alto rendimiento en CPU.

Data-Oriented Design

Frente al pensamiento orientado a objetos, DOD organiza los datos en estructuras contiguas en memoria, optimizando caché y permitiendo paralelización natural.

Arquitectura ECS

Entity = identificador. Component = dato puro (IComponentData). System = lógica que itera sobre arquetipos de entidades.

Entities vs GameObjects

Un GameObject contiene lógica y datos acoplados; una Entity es un id ligero y los datos viven en componentes-dato. Lo segundo escala mejor; lo primero es más cómodo para prototipos pequeños.

Components como datos puros

IComponentData son structs ligeros, blittable cuando es posible, optimizados para acceso secuencial.

Systems como lógica

ISystem (struct, recomendado) o SystemBase (clase). Consultan entidades por componente y aplican comportamiento.

Baking flujo de trabajo

Authoring (MonoBehaviour) + Baker convierten en build time GameObjects en Entities. SubScene almacena el resultado serializado.

Jobs y multithreading

C# Job System permite ejecutar trabajo paralelo de forma segura sobre NativeArrays. IJob, IJobChunk, IJobParallelFor son patrones habituales.

Burst

Compilador que transforma C# de alto rendimiento en código nativo SIMD. Activado con [BurstCompile].

NativeArray y NativeContainers

Contenedores con memoria explícita, seguros con Jobs. Hay que liberarlos (Dispose) cuando ya no se usan.

Comparación de rendimiento

No hay una tasa de fotogramas garantizada por usar DOTS. Comparar ambas versiones en el mismo dispositivo, build y carga; medir tiempo de CPU/GPU y memoria, y justificar si la mejora compensa la complejidad.

Limitaciones

  • Curva de aprendizaje superior a MonoBehaviour.
  • No siempre necesario: para 30 objetos interactivos no aporta nada.
  • Algunos flujos siguen siendo más cómodos con GameObjects (UI, animación clásica).
  • Para estudiantes lo recomendable es el enfoque híbrido: XR Interaction Toolkit en GO + DOTS donde la escala lo exige.

Ejemplos de código

IComponentData
// Importa los tipos y APIs utilizados por este script.
using Unity.Entities;
using Unity.Mathematics;

// Define datos de velocidad que ECS puede asociar a una entidad.
public struct Velocity : IComponentData
{
    // Guarda el vector de velocidad utilizado por el sistema.
    public float3 Value;
}
Authoring + Baker
// Importa los tipos y APIs utilizados por este script.
using Unity.Entities;
using UnityEngine;

// Expone datos en el Inspector y los convierte al formato ECS.
public class VelocityAuthoring : MonoBehaviour
{
    // Expone el valor inicial que el Baker convertirá a ECS.
    public Vector3 initial;

    class Baker : Baker<VelocityAuthoring>
    {
        // Convierte los datos del componente de autoría en datos ECS.
        public override void Bake(VelocityAuthoring authoring)
        {
            var e = GetEntity(TransformUsageFlags.Dynamic);
            // Añade los datos calculados a la entidad convertida.
            AddComponent(e, new Velocity { Value = authoring.initial });
        }
    }
}
ISystem con BurstCompile
// Importa los tipos y APIs utilizados por este script.
using Unity.Burst;
using Unity.Entities;
using Unity.Transforms;

[BurstCompile]
// Actualiza el movimiento de las entidades en cada frame.
public partial struct MoveSystem : ISystem
{
    [BurstCompile]
    // Procesa las entidades correspondientes durante cada actualización ECS.
    public void OnUpdate(ref SystemState state)
    {
        float dt = SystemAPI.Time.DeltaTime;
        // Recorre todos los elementos que devuelve la consulta.
        foreach (var (transform, velocity) in
                 SystemAPI.Query<RefRW<LocalTransform>, RefRO<Velocity>>())
        {
            transform.ValueRW.Position += velocity.ValueRO.Value * dt;
        }
    }
}
IJobParallelFor
// Importa los tipos y APIs utilizados por este script.
using Unity.Burst;
using Unity.Collections;
using Unity.Jobs;
using Unity.Mathematics;

[BurstCompile]
// Actualiza posiciones en paralelo, utilizando un índice por elemento.
public struct MoveJob : IJobParallelFor
{
    public NativeArray<float3> positions;
    [ReadOnly] public NativeArray<float3> velocities;
    // Guarda el tiempo transcurrido para obtener movimiento independiente del frame rate.
    public float dt;

    // Actualiza el elemento correspondiente al índice recibido.
    public void Execute(int i) => positions[i] += velocities[i] * dt;
}
