Preparación técnica opcional

Configuración del entorno

Esta guía sirve como preparación técnica inicial para los laboratorios del curso Diseño de Experiencias Inmersivas. El objetivo es dejar listo un entorno de trabajo estable para crear experiencias con Unity, OpenXR, XR Interaction Toolkit, AR Foundation, ARCore y DOTS (Entities, Burst, Mathematics), y poder generar builds de prueba para PC y Android.

Uso recomendado

Completar antes de la primera clase o utilizar como referencia diagnóstica. No forma parte de las dos horas de Lab 1 y no cuenta para la finalización de las 15 sesiones.

Convención de rutas del curso

Todas las rutas parten de la raíz local del proyecto: Project → Assets → _Project. Cuando se utilicen recursos importados por un paquete, la ruta se indicará desde Project → Assets → Samples.

Pasos de configuración

1

Instalar Unity Hub

Disponer de Unity Hub como gestor de versiones y proyectos.

Unity Hub centraliza la instalación de versiones del editor, los módulos por plataforma y la creación de proyectos. Es el punto de entrada de todo el flujo de trabajo.





Verificación



Resultado esperado

Unity Hub queda instalado y con sesión iniciada.

Recomendación

Usar siempre la última versión estable de Hub para evitar incompatibilidades con Unity 6.

2

Instalar Unity 6 LTS con módulos

Tener el editor Unity 6 LTS con los módulos necesarios para XR, AR y builds Android/PC.

Desde la pestaña Installs de Unity Hub se selecciona la versión 6 LTS y se añaden los módulos requeridos para el curso.





Verificación



Resultado esperado

Unity 6 LTS está listo para crear proyectos con soporte XR, AR y builds Android/PC.

Recomendación

No instalar varias versiones LTS simultáneas si no es necesario: ocupan mucho espacio.

3

Crear el proyecto inmersivo-curso (3D URP)

Crear el proyecto base sobre el que se construirán todos los laboratorios.

Se usa la plantilla 3D URP porque es ligera, escalable y compatible con XR y WebGL. El nombre del proyecto debe ser exactamente inmersivo-curso para mantener una organización común.







Verificación


Resultado esperado

Proyecto Unity 6 URP creado con nombre estándar y ruta limpia.

Recomendación

Evitar OneDrive, Dropbox o iCloud como ruta del proyecto: pueden corromper Library/.

4

Revisar Package Manager y los paquetes iniciales

Después de crear el proyecto, completar la verificación de Universal RP, Shader Graph e Input System. Usar In Project para comprobar lo instalado y Unity Registry solo para instalar paquetes ausentes.

5

Instalar XR Plug-in Management

Activar el sistema de gestión de proveedores XR para Windows y Android.

XR Plug-in Management es el punto único desde el que se activan OpenXR, ARCore y otros proveedores XR por plataforma.





Verificación


Resultado esperado

El proyecto puede activar proveedores XR por plataforma.

6

Habilitar OpenXR (Windows y Android)

Activar el estándar OpenXR para Meta Quest y otros dispositivos compatibles.

OpenXR permite que la misma experiencia funcione en distintos headsets compatibles. Hay que activarlo en las dos plataformas que se usarán durante el curso.






Verificación



Resultado esperado

OpenXR queda configurado en ambas plataformas con un Interaction Profile válido.

7

Activar Input System (new)

Cambiar al nuevo sistema de entrada de Unity, requerido por XRI.

El XR Interaction Toolkit usa Input System (new). Hay que cambiar Active Input Handling y reiniciar Unity.





Verificación


Resultado esperado

Input System nuevo activo y disponible para XRI.

Recomendación

Usar Both solo si se necesita compatibilidad con scripts antiguos.

8

Verificar XR Interaction Toolkit y Starter Assets

Seguir la preparación XR del Lab 1. Comprobar XRI en In Project e instalarlo desde Unity Registry solo si falta. Importar Starter Assets y el simulador desde Samples si aún no se han importado.

El XR Origin sustituye a la Main Camera tradicional. Define la posición del usuario, la cámara HMD y los controladores en el espacio virtual.

Resolución de problemas

OpenXR no aparece como opción

XR Plug-in Management aún no está instalado o no se ha reiniciado el editor tras la instalación.

Solución

Instalar XR Plug-in Management desde Project Settings y reiniciar Unity.

Conflicto entre Input System nuevo y antiguo

Active Input Handling sigue en Old o no se ha reiniciado el editor.

Solución

Project Settings → Player → Active Input Handling: cambiar a New o Both y reiniciar Unity.

El headset Meta Quest no se detecta por USB

Cable sin datos, Developer Mode desactivado o permisos no concedidos en el visor.

Solución

Usar cable USB 3 de datos, activar Developer Mode desde Meta Horizon y aceptar el permiso al conectar.

El build de Android falla

SDK/NDK/JDK mal instalados, Minimum API Level demasiado bajo o backend Mono en lugar de IL2CPP.

Solución

Reinstalar módulos desde Unity Hub, fijar Minimum API 29+, IL2CPP y ARM64 en Player Settings.

La cámara AR no detecta planos

Iluminación pobre, superficies homogéneas o permisos de cámara no concedidos.

Solución

Mejorar iluminación, usar superficies con textura y comprobar permisos de cámara en el dispositivo.

Paquetes DOTS con errores de versión

Entities, Burst y Mathematics en versiones incompatibles entre sí.

Solución

Verificar Entities estable 1.4.x y dejar que Package Manager resuelva Burst, Collections y Mathematics; no igualar sus números de versión.

Library/ subido al repositorio por error

.gitignore añadido después del primer git add.

Solución

Eliminar Library/ del índice con git rm -r --cached Library y volver a commitear.
